## 本轮规则与 API

`events/kind_map.py` 是唯一规则事实源，每行一条 literal rule。`scripts/validation/generate_kind_map.py` 生成 Go production table，`--check` 和测试验证无漂移；生产 direct/file 两条入口均使用同一 `nativeRecord`/`nativeReceipt`，无独立回放映射表或回放专用认知规则。

Edit/Write/MultiEdit/apply_patch → edit_file；Grep/Glob/WebSearch/WebFetch/web.run → search；ReadPaper 原识别保留。明确 namespace 仅 `functions.`、`tools.`、`container.`，剥离一次后仍须符合具体工具语义；exec_command/Bash/shell_command 仅单一 rg/grep 命令可为 search，普通 shell、任意 JavaScript `exec`、未识别工具及结果记录仍 unknown。Codex function_call/custom_tool_call 共用工具规则，参数分别来自 arguments/input；未解释或执行其中的代码。

assistant 文本 read_paper 阈值固定为 **1 个 marker**：大小写不敏感的完整词 arxiv/pdf 或 arxiv.org/abs、arxiv.org/pdf URL。仅实际 text/output_text 与 agent_message 文本参加，thinking/refusal、user 消息、header、token usage/task_complete 不产生该 kind；普通 tool Read(file=paper.pdf) 仍不推断深读。该 kind 的 depth 保持 unknown，不能凭 marker 产生 deep-read signal。Claude 一条消息混合多个不同 tool kind 仍保持 unknown。

root 复核明确：**git commit 命令调用不是已提交事实**。删除原 shell_commit 三规则并调整既有断言；命令失败/未知不构造 commit，也不与真实 log 双计。只有 `MapGitLogRecord` 接受实际 git log record 的完整 commit ID+TS，生成 source=manual、source_kind=git_commit、origin=`git:<commit_id>`；unknown tokens/depth/outcome 保持，不赋成功。
