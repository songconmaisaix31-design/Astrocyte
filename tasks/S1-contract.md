# S1 Attention integration contract

Owner W0, branch `s1-contract-1009`. The Go boundary is `internal/attention/app/contracts.go`; HTTP schemas are `contracts/openapi.yaml`, generated TS is `web/src/api/schema.d.ts`. Keep prior required fields; all new fields on existing resources are optional in v1.

W1 implements `AttentionService` and owns all state rules. W2 implements `Repository`, `SourceReader`, `ObjectStore`. W0 owns HTTP, migrations and composition. No HTTP SQL or provider calls. No Mission/admission/approval execution in S1.

`Repository.WithTx` runs a callback in a serialized transaction, rolling back on any error. Absent loads/finds return `apierrors.NewNotFound`. Saves compare aggregate Version (distinct from content CurrentRevision/opportunity Revision), with 0 meaning create; conflicting CAS returns `version_conflict`. SaveMaterial preserves all immutable prior revisions, source key uniqueness and (material,digest) uniqueness. SaveOpportunity preserves all prior revisions/reviews. SaveJob persists Payload and Caller separately because their JSON tags intentionally hide these fields from HTTP. Receipt keys are caller ID + command name + Idempotency-Key; receipt Digest binds exact semantic input and Result is the complete response. AppendEvent shares the transaction. Never do source/provider/object I/O inside a callback.

ImportedSource distinguishes actual source Text, Summary and binary Attachments. W1 publishes every object before persisting revision references. The digest identifies actual source bytes, never the caller's assertion. SourceReader validates adapter-derived canonical key/locator and any nonempty supplied digest. `content_digest: ""` and `source_key: ""` request server computation for remote sources; the fields remain required for existing v1 callers. arXiv must preserve a versioned PDF/HTML attachment; an Atom abstract alone is not full paper text. summarize output provenance records the real processing source/version and mode; absent transcript positions remain absent. Manual records are explicitly marked manual and do not pretend to be automatic summaries.

`AttentionService` queries take a trusted Principal where records need identity; existing list methods retain S0 shape. Reads do not count human activity. Explicit human RecordUse increments attention. Principal is never decoded from body fields. Transport uses local human session cookie + CSRF for writes. User steering now requires explicit material selection/rules before Agent access: a valid bearer identifies the Agent but grants no data access. Until that permission contract is decided all protected Agent reads fail closed, including lists, derived records and attachments. Agent-bearing session-bootstrap requests are denied. Future authorized machine use remains separate from human attention. Admissions remain S2/501. CommandMeta contains request_id, expected_version and transport-supplied idempotency key. Create expected_version is 1; persistence expectedVersion 0 means new row. Existing material content version and opportunity revision are pinned in SourceRef.

Distillation input_refs (including locator/span) + stage + processing_config + question form reuse identity. Records carry real manual output; fixed inputs without a new question reuse existing output rather than invoke paid work. W1 validates the three layers. The exact ready-for-review theme gate remains a user decision; automatic processing uses the confirmed local Codex path below. A draft record is not evidence of automatic generation. Four dimensions preserve null/unknown; no automatic aggregate scoring until a user profile exists. Reviews affect the stated version and retain later as deferred, not a negative taste sample.

Job payload/caller/operation ID survive restart. W1 owns bounded workers, retry ceiling/deadline, cancellation and recovery rules; W2 supplies atomic CAS in the existing SQLite transaction. Only one worker can change queued to running. Unknown external outcome is preserved as delivery_unknown and is not blindly retried. W0 wrote actual 003 DDL from W2's exact storage requirements.

## Confirmed domain and @file extension

User confirmation: a human @file in a project top-level space creates a reference; the original material remains in its prior classification. The technical snapshot uses an existing SourceRef (material ID + explicit immutable revision + canonical locator). W1 derives locator from that revision rather than trusting an arbitrary object path. An explicit new reference can update the pinned revision, without overwriting source history or silently following future revisions. Removal drops the space reference only. No Mission/Workspace approval/file copying, and classification does not grant access.

`MaterialDomain` is a human classification record, with independent Version. Material.DomainIDs contains explicit membership IDs. `ProjectSpace` is an Attention projection of human references, not a new Workspace project aggregate or work directory. Its MaterialRefs and independent Version support list/get/create/reference/remove. All new services take Principal, currently human only. Agent direct/indirect reads are still denied pending the user scope decision; @ insertion itself is not an unspecified recursive grant.

HTTP routes: GET/POST `/material-domains`, PATCH `/material-domains/{id}`, PUT `/materials/{id}/domains`, GET/POST `/project-spaces`, GET `/project-spaces/{id}`, POST `/project-spaces/{id}/references`, POST `/project-spaces/{id}/references/remove`. Client method names exactly follow service names. New records use expected_version 1; classification assignment uses material aggregate Version; references/removal use project-space Version. All writes retain the same session, CSRF and idempotency boundary. Classification empty IDs remove memberships; domain records are not deleted by this command.

Migration 004 has `attention_domains(id,version,data)` and `attention_project_spaces(id,version,data)`; six List/Load/Save transaction methods use the same CAS/receipt/outbox transaction. Material memberships live in existing aggregate JSON; sources/revisions/objects are unchanged. Failed assignment/reference writes roll back state and human signals. Successful human classification/@ signals may affect attention ranking exactly once; sort policy never expands read permissions.

Material optional ranking fields are `ranking_strategy`, `ranking_reason`, `attention_half_life_seconds`, `attention_weights`. W1 projects actual algorithm and configured parameters. Candidate four-dimensional values remain independent and unknown; a material attention order is not a candidate composite score or an access grant.

## Confirmed automatic processor

The user selected the existing local Codex CLI and authorized processing the supplied public arXiv/Bilibili sources. No private-library export is authorized. W2 exclusively implements `internal/adapters/distillers/`. `Distiller.ConfigurationID(ctx)` describes actual frozen CLI/model/isolation configuration without paid calls or credential export; W1 includes it in reuse identity. `Distill(ctx,input)` receives only selected snapshots (fixed SourceRef, canonical source key, title, text, summary, digest and original provenance), job/operation identity, stage/config/question. It gets no SQL, arbitrary objects/files, human credentials or self-assigned authority.

The model business output schema is `contracts/distillation-output.schema.json`, embedded by `contracts/embed.go`. Processor Provenance (including actual Model) is assigned by the adapter from runtime facts, not the generated body. All returned source references must remain within explicitly selected allowed input versions. Missing source text/evidence remains explicit; an arXiv abstract is not a full-paper summary. Manual RecordDistillation cannot accept automatic provenance.

`AutomaticDistillationService.RequestDistillation` is a narrow optional interface; POST `/distillations/jobs` queues an actual durable job and uses the same session/CSRF/key boundary. Job.DistillationID links the completed result. Fixed inputs+effective configuration+question reuse original job/result without a second model call. Failure/restart/cancellation after external start preserves original operation identity and unknown effects. Native process policy and denial of loopback/MCP bypass require W2's actual probe; unsupported setup stays blocked/failed, with no fake summary or silently chosen provider.

The local browser session bootstrap trusts the local owner. An arbitrary local process without an Agent header can call it; Origin/CSRF and bearer default-deny do not provide OS identity or arbitrary CLI containment. The managed processor must actually deny tool execution and loopback/MCP data reads, and this interface supplies only selected text. The accepted runtime policy is stated below; it does not prove OS read isolation. No global OS or Codex permission configuration is changed by the contract.

The coordinator accepted W2's later native Codex 0.162.0 text-only inference probe. Runtime flags deny execution despite code-mode tool descriptions remaining visible; the tested loopback count was zero and a random sentinel was not exposed. This is a verified runtime denial for the managed invocation, not a successful OS read-isolation claim. Earlier legacy sandbox probes failed and partially changed ACLs; preserve those observations and do not rerun setup or claim rollback. Startup source allowlists are explicit and default deny; this run authorizes only the supplied public paper/video, with no private-library export.

`GET /distillations/processor` reports factual availability, effective configuration/model or null, allowed source keys and a required action. Selected immutable `prior_distillation_ids` become validated `DistillationInput.PriorDistillations`; their source refs must lie in the selected input scope and their identities join reuse. Optional `candidate_suggestion` is actual processor output (nullable when absent), not a server template; creating/revising a candidate remains a human command with evidence, purpose, next step and four unknown-preserving dimensions.

## Candidate profile and entry composition

`RankingProfileService` GET/PUT `/attention-ranking-profile` uses an explicit versioned single profile, fixed ID `attention`, expected_version CAS and the existing human session/CSRF/idempotency boundary. No profile means manual candidate order. W1 owns the valid four weights and primary goal-progress rule; W2 implements the narrow `RankingProfileTx` load/save extension. Migration 005 stores current and immutable prior profile versions, with no seeded weights. Unknown dimensions stay unknown and do not turn into zero-valued evidence.

Material.domain_ids is explicitly emitted even when empty; it remains optional in the compatible v1 schema for older clients. Human `mention` and `project_reuse` are explicit RecordUse actions alongside existing actions. A new @ reference action can add its human attention signal once; replaying the same Idempotency-Key cannot add another signal. The A→B→A source-head decision and ready-for-review theme gate remain user decisions.

Formal entry uses `ASTROCYTE_SUMMARIZE_CLI` absolute installed summarize 0.21.8 JavaScript path and optional `ASTROCYTE_NODE` absolute executable override. With no extractor configured, arXiv remains metadata/PDF-only; with explicit extractor configured, the reader preserves official versioned HTML/PDF, real extracted text, spans and original summarize JSON. No model call occurs in this extraction path. Bilibili page-only input still fails `evidence_missing`. Invalid explicit tool paths fail startup rather than silently switch tools.
