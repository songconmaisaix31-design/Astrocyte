# 首版可控 Swarm CLI

## 用户目标与完成条件

2026-10-20 用户明确首版目标：“抽取 Orca CLI 对应的执行能力，交付一个用户能从原有 Agent 或终端调用的可控 Swarm CLI。”本任务为当前首版事实源，整体主线与历史整理沿 [META_PLAN](../docs/META_PLAN.md) 和[总任务](swa-mainline-20261020.md)接续。

用户能够从已有 Agent 的命令工具或普通终端调用产品入口，执行获准任务并查询实际状态，取得结果，对执行进行明确控制。具体控制命令、执行者所有权、停止与接续、幂等和持久性依据 Orca 实现及现有产品服务形成完整方案，经测试计划审核后实现和真实验证。CLI 输出同时支持终端用户与 Agent 消费，错误和未知执行效果保持真实。

用户进一步明确首版必须找到本机注册的 Agent，并通过 Swarm CLI 调用这些真实 Agent；使用 REA 对 Orca 交付物进行逆向分析，抽取 CLI 对应能力，减少运行依赖与环境耦合。分别记录注册来源、已安装、已配置、可启动及原生控制能力，不能以固定 SDK 或模型可用代替注册 Agent 的实际调用。依赖只按真实执行闭包保留，必要资源和许可随包；实际闭包、独立安装及本机 Orca 保全均须验证。

用户随后补充“将orca cli逆向后参考”。本机实际CLI的PE/Rust静态证据和真实命令目录的限定JS分析已完成，准确对象、Evidence、调用语义及覆盖限制见[CLI实现参考](../docs/standards/swa-orca-cli-reference-20261021.md)。使用这些实际行为指导本产品能力与依赖选择，保留源码复用许可与既有贡献；最终运行闭包继续由构建和独立安装验证，不能据整个上游源码或静态未连边推断需要保留或可以删除。

用户进一步确认：最终验收使用**安装后的同一候选**，完成一次至少包含两个真实 Worker 的任务，并验证并发、停止和成果获取。必须证明两个真实 Worker 在该任务中并发工作，分别查询其身份、状态和输出，指定停止一个 Worker 后核实实际退出及其他 Worker 保全，取得真实任务成果。开发树运行或多份候选分别完成局部检查均不能代替这次安装验收。
