# 首版可控 Swarm CLI

## 用户目标与完成条件

2026-10-20 用户明确首版目标：“抽取 Orca CLI 对应的执行能力，交付一个用户能从原有 Agent 或终端调用的可控 Swarm CLI。”本任务为当前首版事实源，整体主线与历史整理沿 [META_PLAN](../docs/META_PLAN.md) 和[总任务](swa-mainline-20261020.md)接续。

用户能够从已有 Agent 的命令工具或普通终端调用产品入口，执行获准任务并查询实际状态，取得结果，对执行进行明确控制。具体控制命令、执行者所有权、停止与接续、幂等和持久性依据 Orca 实现及现有产品服务形成完整方案，经测试计划审核后实现和真实验证。CLI 输出同时支持终端用户与 Agent 消费，错误和未知执行效果保持真实。

## 已知起点与待决边界

- 当前真实 Orca 为 `1.4.230`，本项目开发已使用其公开 CLI 管理独立 Worker、工作树、持久消息、状态和停止/释放流程。能力说明来自实际二进制的 `skills get orca-cli` 与 `skills get orchestration`，安装不代表所有能力已验证。
- 规范上游为公开 `stablyai/orca`；正在取得对应 `v1.4.230` 源码，准确 Commit、依赖、执行层与桌面耦合在读取后登记。不得从空的本地 Agent-Graph 工作目录推断已有可复用实现。
- 现有 SWA 产品历史、Go/TypeScript/SQLite、Workspace/Swarm 服务和数据继续保留。抽取范围、技术边界及状态归属在源码调查后决定，不建立重复任务账本。
- 首版是否必须脱离 Orca 桌面独立运行已向用户询问，尚未回答。依赖该答案的接口与执行方式保持未决定；源码阅读、许可核对、能力和依赖清单继续。
- MCP 扩展、完整 S3 闭环、研究实验和对外正式发布按各自任务条件处理。现有工具/资料限制继续按原适用范围核实。

## 执行与验证安排

主 Agent 维护范围、决定、计划、资源、集成与最终检查。现有 M0 Worker 完成来源和治理文档整合；M1 契约故障计划已获独立接受，暂未开始动态执行，按首版需要安排窗口。首版执行能力由一名 Worker 负责完整模块、测试和返修，独立 Reviewer 自行推导验收，具体 Task、Worktree、Branch 和 write_paths 在方案明确后登记。

Worker 先对准确上游形成有来源的能力映射：启动与任务投递、执行身份、进程/会话观察、输出与产物、停止、接续、所有权和资源回收，以及这些能力实际依赖的运行后台。明确可直接抽取、需要适配和未知部分；保存上游许可与归属。方案必须覆盖用户可观察的完整调用路径及失败路径，不以命令外观或空处理器作为完成。

实施前提交针对该方案的测试计划；使用真实已安装 Agent、真实任务与工作目录及实际进程/存储。重复提交、客户端断开、停止未知和旧执行者的权限按实际边界验证，不使用替身或伪造原生协议。安装、编译、服务和动态检查遵守 [RESOURCES](../docs/RESOURCES.md) 的唯一窗口；未取得窗口时仅静态工作。

当前结果：已记录最新目标并通知现有 Worker/Reviewer调整接续范围；尚未确定执行边界，尚未编写首版执行代码或运行验收。
