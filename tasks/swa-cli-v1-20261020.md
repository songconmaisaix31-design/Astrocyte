# 首版可控 Swarm CLI

## 用户目标与完成条件

2026-10-20 用户明确首版目标：“抽取 Orca CLI 对应的执行能力，交付一个用户能从原有 Agent 或终端调用的可控 Swarm CLI。”本任务为当前首版事实源，整体主线与历史整理沿 [META_PLAN](../docs/META_PLAN.md) 和[总任务](swa-mainline-20261020.md)接续。

用户能够从已有 Agent 的命令工具或普通终端调用产品入口，执行获准任务并查询实际状态，取得结果，对执行进行明确控制。具体控制命令、执行者所有权、停止与接续、幂等和持久性依据 Orca 实现及现有产品服务形成完整方案，经测试计划审核后实现和真实验证。CLI 输出同时支持终端用户与 Agent 消费，错误和未知执行效果保持真实。

用户进一步确认：最终验收使用**安装后的同一候选**，完成一次至少包含两个真实 Worker 的任务，并验证并发、停止和成果获取。必须证明两个真实 Worker 在该任务中并发工作，分别查询其身份、状态和输出，指定停止一个 Worker 后核实实际退出及其他 Worker 保全，取得真实任务成果。开发树运行或多份候选分别完成局部检查均不能代替这次安装验收。

## 已确认实施顺序

| 阶段 | 实施结果与验收要求 |
| --- | --- |
| 1 固定抽取范围 | 固定 Orca 准确来源、必要源码/运行后台/依赖及原许可；列出直接复用、适配与保留的范围，形成完整调用路径，禁止只交付命令外观 |
| 2 无界面执行、身份与控制规则 | 接入 Orca 无界面执行和真实控制端身份；定义任务/Worker归属、目标选择、输入、查询、输出、停止/退出/释放、幂等和未知结果的 CLI 规则，沿真实能力验证 |
| 3 多 Worker 流程 | 从用户原有 Agent 或终端完成同一任务的多 Worker 执行、并发观察、明确控制和成果获取，保持各自上下文、输出和所有权 |
| 4 失败与资源处理 | 验证启动/输入部分失败、断开/超时未知、重复请求、指定停止失败与实际退出、资源占用/回收；保留真实失败和未知，不重发未知输入或终止非所属进程 |
| 5 安装包 | 从准确源码形成可安装候选，在独立位置安装；用安装后的同一候选完成至少两个真实 Worker 的一次任务及并发、停止、成果获取验收 |

MCP、网页重构、完整旧 S3 和全部历史分支清理已移入后续整合任务。旧 S3 继续保留自己的规格、决定、失败/未验结果及验收记录；本首版不承担其完整验收，也不将旧 S3 的完成状态改写为通过。新 CLI 仍遵守适用的真实来源、工具、项目及数据权限。
